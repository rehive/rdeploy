Version 0.6.0, unreleased
===============================
- New `rdeploy secret` commands manage a service's secrets in Google Secret
  Manager, as loaded by the rehive-service chart 1.4.0+ (`secretManager` in
  the values file), so service repos no longer need their own
  `scripts/secret`:
  - `rdeploy secret list <config>`: each secret and its newest version,
    never values.
  - `rdeploy secret set <config> <KEY>`: adds a version from a hidden prompt,
    stdin or `--generate`, creating `<environment>--<service>--<KEY>` if
    it's missing.
  - `rdeploy secret check <config>`: exits nonzero unless every key in
    `secretManager.keys` has an enabled version.
  - `rdeploy secret restart <config>`: restarts the release's deployments so
    pods read the new values.
  - `rdeploy secret migrate <config>`: copies values from the namespace's
    Kubernetes Secrets (`--map KEY=secret/field`, `--dry-run`).
  Values are passed to gcloud on stdin; they're never printed, put on a
  command line or written to disk. Under certificate-based access, rdeploy
  uses Secret Manager's regional mTLS endpoint.
- `rdeploy upgrade` checks the secrets before running helm when the values
  file has `secretManager.enabled: true`, so a missing secret fails the
  release straight away instead of leaving pods in ContainerCreating until
  the timeout. `--no-secret-check` skips it.
- `rdeploy upload-secrets` and `rdeploy decode-secret` (Kubernetes Secrets)
  are deprecated in favour of `rdeploy secret`.

Version 0.5.7, unreleased
===============================
- `rdeploy upload-static` now runs `gcloud storage rsync` in one process
  with 16 threads. With certificate-based access and an on-disk client
  certificate (the usual Linux setup), gcloud's parallel worker processes
  overwrite each other's `~/.config/gcloud/caa_cert.pem`, so some files
  failed with "ERROR: [SSL] PEM lib" and were never uploaded. Set
  `CLOUDSDK_STORAGE_PROCESS_COUNT` or `CLOUDSDK_STORAGE_THREAD_COUNT` to
  override.

Version 0.5.6, unreleased
===============================
- `rdeploy upload-static`, `rdeploy create-bucket` and
  `rdeploy create-public-bucket` now use `gcloud storage` instead of
  `gsutil`. Under certificate-based access, `gsutil` doesn't send the device

  longer in `var/www/static`, as `gsutil rsync -d` did.

Version 0.5.5, unreleased
===============================
- `rdeploy install` and `rdeploy upgrade` no longer need the
  `containeranalysis.occurrences.list` permission to download a chart from
  Artifact Registry. They used `gcloud artifacts docker images describe` to
  find the chart's digest, which also queries Container Analysis, and failed
  with "Permission 'containeranalysis.occurrences.list' denied" for anyone
  without it. They now list the chart's versions instead, which only needs
  read access to the repository.

Version 0.5.0, Fri 20 Nov 2026
===============================
- New `rdeploy kubectl-login` signs kubectl in to GKE under Google Cloud
  certificate-based access (CBA). It reads a CBA-exempt Desktop OAuth client
  from Secret Manager with your gcloud login, signs in through it (loopback +
  PKCE) asking only for `openid email container.read-only`, writes an
  `authorized_user` credentials file (0600), adds any missing clusters to the
  kubeconfig and points their contexts at a `gke-gcloud-auth-plugin` user
  that uses those credentials. Clusters are discovered with
  `gcloud container clusters list`. The project comes from `--gcp-project`,
  `RDEPLOY_KUBECTL_PROJECT`, the settings saved on the first run, or the
  current directory's `rdeploy.yaml`; the secret from `--secret`,
  `RDEPLOY_KUBECTL_SECRET`, saved settings, or the default
  `kubectl-oauth-client`. Run from a project directory, it needs no flags.
- `rdeploy kubectl-login --status` checks whether the saved session is still
  valid and prints the command to sign in again if not.

Version 0.4.3, Thu 19 Nov 2026
===============================
- Every kubectl and helm command rdeploy runs now names the config's kube
  context and namespace explicitly (`--context`/`--namespace` for kubectl,
  `--kube-context`/`--namespace` for helm) instead of relying on the
  kubeconfig's current context and namespace. That state is shared by every
  terminal on the machine, so switching namespace elsewhere (e.g. `kubens`)
  while a command ran could send it to the wrong namespace. An atomic
  `helm upgrade` resolves the namespace again when it rolls back, so a
  rollback could recreate the release's objects in another namespace.
- Covers `upgrade` (and its rollout progress display), `install`, `helm`,
  `live-image`, `upload-secrets`, `decode-secret`, `create-namespace`, and
  the management pod started by `shell` and `manage`.
- `set-context` still switches your local kubectl to the config's cluster
  and namespace, but rdeploy's own commands no longer depend on it.

Version 0.4.1, Wed 28 Oct 2026
===============================
- `rdeploy helm-setup` and the local helm path now use the machine's CPU
  architecture, so Apple Silicon Macs get the native `darwin-arm64` build
  instead of the x86_64 one (which fails without Rosetta, e.g. on macOS 27).
  Linux arm64 gets `linux-arm64`. Unsupported architectures raise an error
  instead of falling back to amd64.
- `rdeploy helm-setup` now runs `helm version` on the binary it installed and
  fails with the error if it can't run, instead of printing
  "Successfully installed".

UPGRADE NOTES:
- On Apple Silicon, run `rdeploy helm-setup <config>` once to download the
  arm64 binary to `opt/helm-v<version>/darwin-arm64/`. The old
  `opt/helm-v<version>/darwin-amd64/` directory is no longer used and can be
  deleted.

Version 0.4.0, Fri 10 Jul 2026
===============================
- `rdeploy upgrade` now shows live rollout progress while the atomic helm
  upgrade waits: it polls `kubectl get pods` and shows the pod status table
  (prefixed with `[rollout]`), so you can watch pods being created, pulled,
  started and terminated (including helm hook pods such as migration jobs)
  instead of blocking silently. On a terminal the table is pinned to the
  bottom of the screen and updates in place while helm's output scrolls
  above it; on a non-TTY (e.g. CI logs) it prints the table once, then any
  row that changes.
- Added `--no-progress` to disable the live progress display. The display is
  purely informational and runs concurrently with helm; helm `--atomic`
  remains the sole arbiter of success, failure and rollback, and the watcher
  never affects the command's exit code.

Version 0.3.0, Thu 09 Jul 2026
===============================
- `rdeploy upgrade` now runs helm with `--atomic` by default: helm waits for
  the rollout to complete (up to `--timeout`, default 15m) and automatically
  rolls back to the previous release if it fails, and the command exits with
  an error instead of reporting success.
- Added `--no-atomic` to restore the previous fire-and-forget behaviour and
  `--timeout` to adjust how long helm waits.

BREAKING CHANGES:
- `rdeploy upgrade` now blocks until the rollout completes and exits non-zero
  on failure. Scripts that relied on it returning immediately should pass
  `--no-atomic`.

Version 0.2.0, Thu 09 Jul 2026
===============================
- Upgraded all dependencies to current versions: invoke 2.2+/3.x, semver 3.x,
  kubernetes 28+, packaging 23+, python-dotenv 1.0+, requests 2.31+.
- Migrated packaging from setup.py to pyproject.toml.
- Replaced deprecated pkg_resources and distutils.strtobool (removed in
  Python 3.12) with importlib.metadata and a local implementation.
- Added a test suite (pytest).
- Removed all Azure support. rdeploy now targets GCP exclusively. Commands
  fail with a clear error when rdeploy.yaml specifies a non-gcp provider.
- Fixed latest-prerelease regex to escape the version argument.

BREAKING CHANGES:
- Azure support removed: set-cluster, set-context, set-project and cloudbuild
  no longer work with `cloud_provider.name: azure` configs, and the
  `container_registry_provider: azure` setting is no longer honoured.
- `rdeploy upgrade` named argument renamed: `--version` is now `--tag`
  (positional usage, e.g. `rdeploy upgrade prod 1.2.3`, is unchanged).
- The `bash` alias for the `shell` command was removed; use `rdeploy shell`.
- `rdeploy latest-prerelease` named argument renamed: `--version` is now
  `--ver`. The misspelled `latest-prerelese` alias was removed.
- Requires Python 3.9+.
